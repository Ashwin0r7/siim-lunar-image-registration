# Cross-Stage Error Ledger

Every significant failure discovered so far, across all stages. **Nothing here is removed once entered** — a fixed error stays in the ledger with status `FIXED`, because the lesson outlives the bug.

Only failures **documented by repository evidence** are listed. No entries are inferred or invented.

**Severity:** `CRITICAL` would have invalidated published results · `HIGH` corrupts numbers or conclusions · `MEDIUM` affects performance or scope of a claim · `LOW` local/contained.

**A note on what dominates this table.** Of the entries below, **9 are failures of *evidence* rather than of code** — metrics that lied, thresholds validated circularly, conclusions over-generalised from one terrain. Only 5 are ordinary software defects. That ratio is itself the project's main empirical finding.

*(That sentence was written when the table ended at E-021, and its arithmetic was already flagged as discrepancy **D3** in [`README.md`](README.md#discrepancies-found-during-re-verification). It is left exactly as written — integrity rule 3 — rather than restated each time the table grows. **E-022 … E-026 were appended on 2026-08-25** from the REAL-DATA stage; of those five, two are ordinary implementation bugs (E-022, E-025), two are failures of evidence in new measurement code (E-023, E-024), and one is a genuine negative result about a selection criterion (E-026). The qualitative point — evidence failures are at least as common as code defects — survives the addition. **E-027 … E-029 were appended on 2026-08-26** from REAL-DATA-02; all three are **design mistakes, not code defects**, and the 260-test suite in place at the time was passing throughout and could not have caught any of them. **E-030 and E-031 were appended on 2026-08-26** from REAL-DATA-03; both are ordinary implementation bugs in existing code, and both were caught by this stage's data before they reached a reported result.)*

## Patterns worth carrying forward

1. **Five of the most severe entries (E-001, E-005, E-008, E-009, E-014) were invisible to every self-reported metric.** Each required an external reference — physical resampling, ground truth, disjoint validation seeds, or published lunar statistics. Self-consistency is not evidence.
2. **Two entries (E-005, E-010) were errors in the *evaluation* code, not the pipeline.** Harness bugs are more dangerous than pipeline bugs because they corrupt every conclusion at once and tend to flatter.
3. **E-007 was hidden inside idiomatic code.** Stage-level timing, not code review, found it.
4. **E-013 → E-014 → E-015 are one causal chain**: an unvalidated dataset assumption propagated into two wrong conclusions. Validate the *generator* before trusting anything measured on it.
5. **Six entries are over-claims rather than defects** (E-008, E-009, E-014, E-015, E-016, E-018). The dominant risk in this project is not broken code; it is **believing a result more than the evidence supports**.
6. **The same failure modes recur in new code, and recognising the recurrence is what makes them cheap to find.** E-023 *is* E-010 — a statistic collapsing onto a sentinel — occurring in measurement code written eight months later. E-022 *is* E-019 — a service returning a successful, well-formed, wrong response. E-021 was itself E-012 reintroduced. **A ledger is only useful if the patterns in it are read before the next module is written**, not after.
7. **An implausible coincidence is a bug report, not a finding** (E-025). Four "different" conditions returning byte-identical numbers had an available scientific explanation, and it was wrong. Assert that inputs differ *before* interpreting outputs that depend on the difference.
8. **A uniformly negative result across conditions can be evidence about the sampling rather than about the variable** (E-028). REAL-DATA-01 tested four line-direction combinations, saw 3/4/4/5 inliers, and concluded the direction hypothesis was not the explanation. Independent geometry later showed **three of those four tile pairs were 11–23 km apart and could not have succeeded**. The inference *"all conditions failed, therefore this variable does not matter"* is valid only if every condition was otherwise capable of succeeding. This is E-025's mirror image: there, identical results across supposedly different conditions were a bug; here, uniformly negative results across genuinely different conditions were read as a finding.
9. **"The data does not decide it" is a statement about the data one has looked at** (E-028). The line direction was correctly judged unrecoverable from the ODE footprint polygon — and the archive index table one directory above the data names its corners outright, along with `LRO_FLIGHT_DIRECTION`. Before concluding that evidence is absent, establish where that evidence would live if it existed.
10. **A lesson recorded in the ledger only protects the file it was learned in** (E-030). E-025's rule -- *encode every varying parameter in the artefact's name* -- was written down, applied to the acquisition script, and then violated in the sanity script one directory away, where it silently fed one tile's bytes into another tile's decode evidence. **When a failure mode is entered here, grep for its shape across the repository**, not just the line that caused it. The three recurrences so far (E-010 -> E-023, E-019 -> E-022, E-025 -> E-030) were each found by recognising the shape, not by a test.
11. **Persist the measurement before rendering it** (E-031). A figure that cannot draw must not be able to destroy checks that have already passed. Ordering the write after the plot is a latent data-loss bug in every analysis script that does it.
12. **If an artefact records a fact, something must fail when that fact is wrong** (E-033). A `stage` field that no test compared against the directory it was written into drifted on its first reuse and stayed wrong through three stages, in files a judge is invited to open. Self-description without verification is decoration. **Either check a recorded field or do not record it.**
